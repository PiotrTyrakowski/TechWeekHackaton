# OpenToVibe: independent Reactor research

2026-10-31 · application snapshot `f2e124d45c220ae9759c585ed74bc611377b6dea` · official kit `f0a317dfa13e7797baae61711cef27a9805bedcc`.

**Recommendation:** establish reliable final-segment citations, improve original-evidence packing without extra calls, then test a bounded memory preload against a matched inline-context control. Memory alone cannot repair the scored evidence ceiling. A source-discovery step must recover original excerpts into the final question's evidence to lift that ceiling.

This is an independent offline audit for the coordinator's Gates 0–4, not an execution plan or access authorization. No production runtime edits, Reactor requests, credentials, access attestations, or test downloads. Official files were read from the existing pinned checkout; remote documentation fetching failed, so deployed limits and subsequent documentation changes are not verified. New reproducible measurements and pure-parser probes are in [offline-audit.json](independent-reactor/offline-audit.json), generated by [offline_audit.py](independent-reactor/offline_audit.py). Gold was used only for evaluation diagnostics.

## Findings that change the experiment priorities

1. **Memory and scored provenance are separate channels.** The guide explicitly requires current `--evidence` even after loading a history. Remembering `s_…`, browsing a source, or emitting `[E1]` without current passages cannot create a submitted source citation. The mapper only translates labels against this call's passage list. [Loading contract][loading], [mapper][parser].
2. **The one unique completed live answer demonstrates a final-format failure.** Reactor correctly answered `Luna`, cited `[E1]` in its narrative, then wrote `# FINAL ANSWER [ref:56451236]: Luna`. The extracted answer contains no label; official local scoring says answer correct, Evidence F1 **0.0**. This neither demonstrates a memory failure nor establishes general answer quality. The revised wrapper has no completed live validation. [Raw response](live-smoke-20261030T2135/results.jsonl), [score](live-smoke-20261030T2135/official-score-details.jsonl), [existing wrapper][wrapper].
3. **A fixed evidence set imposes a hard session-citation ceiling, even with perfect memory.** For current supplied session set `S`, gold set `G`, and `k=|S∩G|`, an oracle citing only available correct sessions gets at most `2k/(|G|+k)`. On the cached 496 answerable dev-large calibrated results, mean all-retrieved-cited F1 is **72.83%**; oracle selective citation could reach at most **85.66%** without adding source IDs. This is a source-set bound, ignores excerpt sufficiency, and includes fitted questions; it is not Reactor performance. Memory may improve answers or reject irrelevant citations within that bound, but cannot cite missing sessions through this mapper. [Cached per-question sources][cached], [new calculation](independent-reactor/offline-audit.json), [scoring function][score].
4. **The natural sequential dev cohort is unusually easy to reuse.** Directly counting public questions plus evaluation-only gold gives 414 singleton histories and 56 two-question histories. All **112 shared-history questions are single-session-assistant**, none abstain, and all **56 pairs have identical gold session sets**. The existing planner's shared cohort therefore tests repeated-source reuse, not ten heterogeneous questions with different sources, updates, and unknowns. Keep it, but label its transfer limit. [Reproduction](independent-reactor/offline_audit.py), [cohort selection][planner].
5. **Sequential citation errors can be syntactically invisible.** In the offline probe, unchanged `Luna [E1]` maps to `s_alpha`, then to `s_beta` after evidence reordering. The parser sees a valid citation both times. Persistent memory retains earlier labels; validation cannot detect reuse of the wrong but valid current label. Test semantic support after deliberate label permutation. [Probe](independent-reactor/offline-audit.json), [mapper][parser].
6. **Native memory cannot retrieve source material it was never shown.** The default only exposes retrieved excerpts; even the targeted preload pools that retriever's excerpts, not all original sessions. Before a discovery trial, measure the union of loaded source IDs and whether their loaded text contains additional useful facts. Without new browsing/input, discovery is bounded by that union. A broader ledger may improve this opportunity but is a changed selection policy that must be disclosed. [Memory constructor][memory], [loading contract][loading].

## Exact API and history contract

| Operation / state | Verified behavior | Experimental consequence |
|---|---|---|
| Dataset history | One user's dated sessions; `h_…` is an input identifier. Session content can recur elsewhere with a different history-local date. | Never cache source dates globally by session ID. Preserve both roles. |
| Reactor history | One active state per hosted agent. Reset is HTTP `POST /agents/{agent_id}/history`; it wipes memory, chat history, pending input and late replies, preserving configuration. Replaced IDs are refused. | A history ID is not an independent concurrently usable session handle. One reset per dataset history per arm; no resets between that user's questions. |
| Normal question | `build_message` serializes question, date, passages, labels and instructions into a single text message. Chat uses `wss://HOST/agents/{agent_id}/ws/chat?history=…`. | There is no separate structured evidence store or model-native citation field. Dataset question ID is local output bookkeeping, not sent to the model. |
| History loading | `--text` sends verbatim text, no question template/ref. It completes on the first eligible reply after the matching acknowledgement. Parts must be sequential; use oldest-first source IDs, dates, roles and a short acknowledgement request. | Every part is a real agent turn. An `OK` reply establishes neither complete recall nor idle server state. Loading replies stay outside predictions. |
| Question completion | Exact matching `ack.text`, then a reply with integer `cycle > ack_cycle` and the current marked ref. Other refs go to late replies. | Model-written refs filter output; they are not transport idempotency keys. Timeout does not prove cancellation. |
| Limits | Client default: 16,000 Python characters for the entire rendered message. Guide: 32,000 server characters at event start, subject to change. | Budget instructions, labels, question and dates too. Raising the client flag cannot raise the server limit. No published dollar price, token quota or request-rate guarantee was found. |

Sources: [guide workflow/evidence][workflow], [official client contract][contract], [transport and retry implementation][transport], [limits/loading][loading].

The documented promise is persistence within a history and isolation between histories. The kit does **not** establish a context-window size, compression policy, retrieval/index architecture, storage quota, recall guarantee, retention duration, memory inspection/search API, per-fact write/delete, snapshots, forks, or old-history restoration. Memory ingestion is ordinary conversation, not hidden structured memory CRUD. Public browsing is documented, but no structured browser-tool interface or authenticated private search contract is exposed by this client. [Guide][browsing], [client][contract].

The current implementation already groups users sequentially, supplies history-local dated evidence, uses the official parser/adapter, and validates citations against each question's evidence/history. Its opt-in `targeted` preload pools verbatim retrieved excerpts across that user's **public questions**, deduplicates, orders by date, and loads a bounded ledger without E labels. It is query-aware context pooling, not whole-history memory or a generated fact database. Its default 12,000-character total budget fits at most one 16,000-character part and may omit excerpts. With roughly ten test questions, do not assume the pooled ledger covers every question. Record retained passages by question. [Runtime preparation][runtime], [memory constructor][memory].

## Final-answer and citation reliability

The guide says only the marked line counts; source code actually extracts the segment after a line-start final marker through the next final marker or the end of that reply. Subsequent physical lines can therefore count. A repeated ref keeps the last segment **within one reply**, but the transport returns the first eligible reply containing a matching final; it does not await later corrections. Use one concise canonical line and regard the accepted final as committed. [Parser][parser], [acceptance loop][transport].

| Offline input | Actual behavior |
|---|---|
| Citation before final marker | Excluded from extracted answer/citations. |
| `# FINAL ANSWER [ref:1234abcd]: Luna` followed by newline `[E1]` | Included in the final segment; do not depend on this tolerance. |
| `Luna [E1] [E2]` or `Luna [E1, E2]` | Mapped and stripped cleanly. |
| `Luna [E1/E2]` or `Luna [source E1]` | Mapper finds labels; adapter leaves bracket text in answer. |
| `[e1]`, bare `E1`, `[s_alpha]` | No mapped citations. |
| `[E0]`, out-of-range labels, `[E1]` with no passages | Unknown labels. |

[Pure-parser reproduction](independent-reactor/offline-audit.json), [extraction][parser], [adapter stripping][adapter].

The original prompt requested evidence citations and then a marked final line, while defining preceding text as interim. A plausible explanation for Luna is that Reactor satisfied the first instruction in its narrative and compressed the final. That is an inference from the prompt/output, not knowledge of model internals. The parser behaved as designed. [Original prompt][prompt].

Specific recommendations:

- Keep the existing wrapper as the candidate; test its effect before adding still more instructions. It already requires a concise current-ref final with supporting current labels, distinguishes roles/dates, and warns against previous labels. [Wrapper][wrapper].
- Use `# FINAL ANSWER [ref:<current>]: <answer> [E1] [E2]`, with uppercase separate bracket labels **only for actual support**. Require every indispensable source for multi-hop answers, without citing all candidates automatically. Label numbers are passage positions, not globally stable IDs.
- Multiple disjoint excerpts from one session may share its real ID/date and receive separate labels; the adapter and scorer deduplicate session IDs. This can recover distant necessary turns without irrelevant middle text. Repeated passages do not create extra citation credit. [Guide][workflow], [conversion][adapter], [scorer][score].
- Measure extracted-final citations after official conversion. Preserve uncited completed answers with actual F1 zero. Never move narrative citations into the final, append retrieved sessions, or select a lucky retry after seeing an uncited answer. Current runtime already validates this boundary. [Validation][validation].
- Use explicit marked `INSUFFICIENT_EVIDENCE` when absent; ordinary “I don't know” does not set the official abstention flag. An actual abstention and a timeout are different outcomes. Report local unjudged answers separately from correct/incorrect answers. [Client status logic][status], [official scoring rules][rules].

## Ranked hypotheses

Costs count initial resets plus chat turns; retries/recovery add calls. Let `H` = users, `Q` = final questions, `P` = preload parts, `M` = intermediate turns. The control costs `H+Q`. Rubric shorthand below is IDEA / HARNESS / APPLICATION from earlier team reports; the official README does not publish that rubric or a benchmark-to-points conversion. These are expected relevance, not awarded points. [Team rubric record](REACTOR_DEEP_DIVE.md), [official scoring][rules].

| Rank / hypothesis | Mechanism and supporting evidence | Speculation / failure modes | Minimal validation; call cost | Expected judging relevance |
|---|---|---|---|---|
| **1. Evidence-only, stronger final instructions** | Put support labels in the parsed final itself. One raw correct-but-uncited answer directly motivates this; wrapper exists. | No live success yet; example labels may be copied, terse output may omit necessary facts/sources, prompt length can dilute instructions. | Fixed-evidence prompt A/B, including multi-source and absent cases. Two arms `2(H+Q)`; no preload. | HARNESS: measurable citations/completion; APPLICATION: auditable answers. Limited IDEA by itself. |
| **2. Dynamic question-specific packing** | Match entity/role/event; give assistant recommendations, user facts, updates, count operands or event anchors as needed. Local preprocessing is explicitly allowed. Existing retrieval reports locate multi-session/temporal gaps. | Test question type is unavailable; never route using gold. Lexical routing can over-trigger, broader retrieval has already reduced precision. Derived hints may anchor a wrong answer. | Keep selected sessions fixed; compare current versus type-inferred formatting/packing. `2(H+Q)`, no extra turns. Verify retained original facts offline first. | HARNESS: evidence sufficiency; APPLICATION: useful temporal/decision answers. |
| **3. Multiple passages from one session** | Preserve distant question/answer or antecedent/recommendation turns under separate labels sharing a session ID. Officially supported; current BM25 uses top turns, calibrated packs only two strongest plus fitting neighbors. | Extra passage overhead, truncation, omission of a third required turn; source recall can look perfect while excerpt answerability fails. | Same sessions and budget, vary within-session passage selection only. `2(H+Q)`; zero additional calls per run. | HARNESS: precise provenance and packing; useful on assistant-fact tasks. |

Documented persistence and implemented targeted path support feasibility. | Recall/latency benefit unproven; selection may miss facts. Generated summaries may lose negation/updates. Cross-question pooling and extra text confound memory claims. | No preload vs inline-identical-ledger vs preload, identical final mappings. Three arms `3(H+Q)+P`. | IDEA/APPLICATION if persistence demonstrably helps; HARNESS if provenance survives. |
| **5. Temporal/multi-hop packaging** | Show old/new assertions and distinct event/session dates, person/object joins, units and supported arithmetic operands; local date/count calculation is encouraged officially. | Newer mention may concern another event; repeated totals can double-count; unknown operands must not be invented. Broad complementary retrieval and cap-only expansion already failed precision checks. | Paired hard-category evidence with/without explicit timeline/operand structure; same originals. `2(H+Q)`. | APPLICATION: changed plans and commitments; HARNESS: reproducible calculations. |
| **6. Sequential same-user reuse** | Prior evidence and replies persist for subsequent questions without explicit preloading. Required by the workflow; zero added turns. | All dev pairs share sources and category; benefit may be repeated-source exposure. Wrong early answers, stale labels or later question dates can contaminate following answers. | Predetermined natural pairs, per-position outcomes, alternate evidence order; compare preload/inline arms, not illegal per-question resets. Base `H+Q`; extra sequence replications need separate fresh arm histories. | HARNESS: isolation and correct reuse; IDEA only if benefit exceeds repeated-source convenience. |
| **7. Reactor discovery then cited final** | From loaded memory ask for bounded stable source IDs, validate membership, rehydrate original excerpts, then ask final with current labels. Uses ordinary `--text`, not a hidden search API. | IDs can be invented or incomplete; first text reply may be only “looking”; acknowledged turn may remain pending. Memory claims are not source evidence. | Small discovery pilot after preload, with predefined fallback and exact original-source rehydration. `H+P+Q+M`; one discovery per question gives `M=Q`. | IDEA: Reactor directs evidence discovery; HARNESS/APPLICATION need measured added value per turn. |

Existing `retrieval_memory.py` experiments are external retrieval, **not** native Reactor memory trials.

Full-history loading is documented but ranks below compact memory. The guide estimates ~125 parts per test history at the default limit: `15 + 146 + 15*125 ≈ 2,036` initial operations, versus **161** evidence-first; this is a guide-based approximation, not measured test sizing. A one-part-per-user preload yields **176**, two parts **191**; adding one discovery per question to the one-part policy yields **322**. No monetary estimate is justified. Each load waits for a real reply; include measured load latency before choosing a batch. [Test setting][rules], [loading sizes][loading].

## Three highest-value experiments for the coordinator

These are later research proposals, not replacements for the coordinator's smaller frozen gate plan or permission to execute them. The coordinator reports the integrated Gate-0 audit/planner at `cc6e6c6` / `371c73c` and a conditional 23-operation incremental schedule; this report audits the earlier `f2e124d` snapshot and does not independently validate those new commits. Freeze IDs, source text, dates, within-user order, prompt versions and pass/fail criteria before any future comparison. Use complete fresh histories for separate arms and retain every completed outcome, including uncited answers.

**1. Citation contract gate, then small prompt A/B.** First run the zero-call parser probes in this report. Under a separately authorized future window, compare original prompt versus existing wrapper on three predeclared questions in three distinct histories: a user fact, a multi-source answer, and an unanswerable near miss. Cost **12 initial operations** (`2*(3 resets+3 questions)`); the previously exposed Luna example can be a separate regression diagnostic, not new accuracy evidence. Require correct final refs, actual supporting final labels, complete necessary session mapping, and a genuine marked abstention for the absent case. Unknown or stale labels fail; transport failures remain incomplete. Three examples establish a gate, not a reliable population error rate.

**2. Original-evidence packing parity.** After the citation gate, use eight distinct development users, two questions from each of assistant-fact, temporal, update and multi-session categories. Freeze source session selection, prompt and total text budget; change only within-session snippets and the chronology/operand presentation inferred from the public question. Gold may stratify evaluation but must not determine the inference route or answer hints. Two arms cost **32 initial operations**. Audit that each operand/claim retains a verbatim source, units, roles and history-local dates. Measure actual final citation F1 and answer judgments; session recall is intentionally unchanged. This distinguishes answer-bearing text loss from retrieval misses and costs no additional turn per production question.

**3. Native-memory ablation with provenance stress.** Select three natural shared dev histories, two questions each. Run A: current evidence; B: exact compact ledger inline as delimited context for each final; C: same ledger once via `--text`, then the same final questions/evidence as A. Keep E mappings identical across corresponding questions/arms; permute source-to-label assignments between question 1 and 2 to expose stale-label reuse. Each arm still uses one history per user. Cost **30 initial operations**: A `3+6=9`, B `9`, C `3+3+6=12`. Fit ledger+final inside the same documented cap; if it does not fit, shrink the frozen ledger identically in B/C, rather than using unequal information. All scored claims must still be supported by the current labeled originals.

Interpret A→B as added-context opportunity and B→C as delivery/persistence difference, with different prompt lengths explicitly reported. Both remain stateful and B repeats context; this is a practical policy comparison, not a proof of hidden memory architecture. The 56-pair dataset limitation prevents a ten-question generalization claim. A later **separate synthetic ten-question same-user diagnostic** can cover changed facts, negation, assistant advice, near misses, unrelated topics and reordered labels; do not fabricate benchmark histories or include it in benchmark accuracy. A no-evidence recall probe is diagnostic only and necessarily has no mapped citations.

If an offline coverage audit shows the ledger contains useful sources missing from a particular final evidence package, an optional discovery arm D on the same three real histories costs **18** (`3 resets+3 loads+6 discoveries+6 finals`), making **48** across A–D. Validate returned IDs against the current history, recover original passages, and measure newly recovered gold sources; reject invalid IDs and use a frozen fallback. Do not count intermediate guesses as evidence or predictions. This is the specific bridge by which native memory could improve scored recall rather than only fluent answers. A ledger containing no extra relevant sources cannot test that mechanism.

A separate reasoning preflight could ask Reactor to resolve one concrete event/entity ambiguity using original conflicting statements, followed by the normal cited final call with those same originals. It costs one extra turn per selected hard case. There is no evidence yet that generic repeated reasoning beats a well-packaged single call; an incorrect intermediate interpretation can persist. Prefer this only after identifying a repeatable ambiguity failure, and score the final independently of the preflight's confidence.

Across experiments report per-question and per-history answer judgment/unjudged status, actual final session F1, necessary-source recall, false abstentions, missing/unknown/stale labels, marker completion, transport failures, initial calls, safe retries, load and answer latency, input size, and question position. With only 15 test users, use history-clustered comparisons for performance claims; dev-large shares dev questions and is a distractor-scale check, not a new holdout. [Dataset cautions](MAXIMUM_SCORE_R2.md).

## Session invalidation and concurrent clients

The raw archives show reset success followed by early close and `history_changed`; a later attempt against the reported current history encountered safe `previous_pending` retries and another replacement. Logs prove invalidation, not who caused it. The team separately reported concurrent use, making contention a plausible explanation; server/provider restart remains another documented close cause. A clean WebSocket close code 1000 is not answer success. [Archived attempts](reliability-diagnosis-20261030/attempts.jsonl), [frame chronology](REACTOR_SUPPORT_PACKET.md), [team update](REACTOR_RELIABILITY.md#reactor-reliability-investigation--2026-10-30), [close causes][loading].

One live runner must own the entire agent window across machines and worktrees. Separate client instances or output folders cannot isolate state on one agent. Parallelism requires separately issued agents. Do not adopt `current_history_id`, reset to clear pending work, or replay an uncertain preload: these can mix users, erase memory, or duplicate ingestion. Only `busy`/`previous_pending` with `forwarded is False` get the official automatic backoff; other failures need classification. A reset failure can be ambiguous (`restart_failed` can already install new state). Current local locking/checkpointing helps cooperating local runners but supplies no server lease or cross-machine exclusion. [Retry source][transport], [failure table][failures], [current safeguards](REACTOR_RELIABILITY.md).

The runtime and reports already implement much of the recommended harness. The unresolved performance questions are model behavior: reliable final citations, evidence sufficiency, memory recall/interference, discovery accuracy, and latency under a complete sequential schedule. This audit changes experiment interpretation and priorities; it does not close any live gate.
